# Pine interface principles

Pine applies Apple-style human-interface thinking without imitating a specific Apple product.
The official principles translate to this CNC application as follows:

- **Purpose and simplicity:** put the current machine task first; remove controls and prose that do not earn their place.
- **Agency:** expose each operator step directly, keep expert tools available but secondary, and make recovery obvious.
- **Responsibility:** remain quiet when healthy, but never hide stale state, hazards, E-stop evidence, rejections, or recovery actions.
- **Familiarity and consistency:** use one semantic color system, one control geometry, predictable placement, concise verb-led labels, and consistent feedback.
- **Flexibility and accessibility:** support keyboard focus, readable type, descriptive control names, visible disabled state, and both minimum supported window sizes.
- **Hierarchy, depth, and deference:** distinguish content from controls with restrained layered surfaces; use spacing and typography before borders or color; reserve blue for selection and primary action.
- **Craft and delight:** use precise alignment, subtle state transitions, balanced radii, and polished details without decorative motion that competes with machine state.

Safety authority remains in the backend. Visual simplification must not weaken an interlock, infer safety from silence, truncate actionable warnings, or make a disabled machine action appear available.

References: [Apple design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles), [layout](https://developer.apple.com/design/human-interface-guidelines/layout), [color](https://developer.apple.com/design/human-interface-guidelines/color), [typography](https://developer.apple.com/design/human-interface-guidelines/typography), and [buttons](https://developer.apple.com/design/human-interface-guidelines/buttons).
